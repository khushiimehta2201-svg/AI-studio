# Teamcenter AI Studio — Definitive Build

A local-first PDF-to-software-training-video system designed around a stable canonical scene contract.

## Core architecture

```text
PDF
  -> document ingestion + OCR
  -> document structure / metadata filtering
  -> procedure + explanation extraction
  -> evidence/screenshot association
  -> target candidate extraction
       OCR + geometry
       optional author highlights
       Qwen vision escalation
       second-pass verification
  -> canonical scenes
  -> contextual narration
  -> TTS
  -> canonical timeline
  -> MP4 + VTT + portal manifest
  -> machine QA
  -> trainer review
  -> publish
```

A screenshot is evidence, not a scene. One screenshot may support multiple actions, and one instructional topic may use multiple screenshots.

## Current models

The tested local configuration uses:

- Ollama text model: `llama3.2`
- Ollama vision model: `qwen2.5vl:7b`
- Ollama endpoint: `http://127.0.0.1:11435`
- Context: `4096`

These are configuration values, not application dependencies. The rest of the application consumes provider-neutral `TextModel` and `VisionModel` interfaces.

To move to a stronger Ollama model, change only the model configuration, for example:

```text
AI_TEXT_MODEL=<new-text-model>
AI_VISION_MODEL=<new-vision-model>
AI_NUM_CTX=<supported-context>
```

To add a different provider, implement the same adapter interface in `model_adapters.py`; planner, targeting, renderer and portal contracts do not need to change.

## Targeting strategy

The targeting engine never assumes that a PDF contains numbered or highlighted controls.

1. Extract likely UI text with OCR.
2. Score candidates using exact/fuzzy label similarity and geometry.
3. Use author highlight/annotation boxes only as evidence hints.
4. Escalate to the configured vision model for unresolved targets.
5. Accept vision targets only after confidence/ambiguity checks and a second visual verification pass.
6. Keep ambiguous or unresolved targets out of the rendered cursor path.
7. Trainer can approve a proposed target or click the screenshot to set the exact point.
8. Drag actions store both source and destination points.

Keyboard-only actions such as `Press Enter` intentionally have no mouse target.

## Document handling

The ingestion stage separates:

- document metadata
- table of contents/index/list pages
- repeated page furniture such as logos
- explanatory prose
- numbered and unnumbered procedure actions
- embedded visual assets
- full-page visual fallbacks
- scanned/image-only pages via OCR fallback

Source numbering is preserved independently from generated scene numbering.

## Canonical scene contract

Every downstream component consumes the plan generated by `production_planner.py`. A scene contains at least:

```text
scene_id
kind
source_page
source_step_number
source_order
action / action_type
target_status
target_review_required
cursor / cursor_path
screenshot
audio/narration references
caption text
timing
interaction_plan
```

The renderer writes the same `scene_id` into the canonical timeline, and the trainee portal uses that timeline rather than dividing video duration into equal action buckets.

## Quality gates

A tutorial is publishable only when:

- plan structure passes QA
- required targets are verified
- verified targets contain valid normalized cursor points
- drag actions have both start/end points
- narration is present and bounded
- rendered MP4 and VTT exist
- video/audio streams are valid
- rendered timeline scene IDs exactly match the plan
- rendered duration agrees with the timeline
- no scene remains in trainer-review state

Generation is therefore separate from publication. A bad or ambiguous generation can be reviewed without being silently exposed to trainees.

## Persistence and security

SQLite stores job state, plan metadata, publication state, prerequisites and scene-review decisions. Generated source files are kept inside a per-job directory.

The application does not statically expose the entire jobs directory. Media endpoints expose only the final tutorial/video-caption artifacts, and trainer-only preview endpoints expose only a selected screenshot within the owning job directory.

Enable authentication for deployment:

```text
AUTH_REQUIRED=true
AUTH_SECRET=<long-random-secret>
TRAINER_USERNAME=<trainer-user>
TRAINER_PASSWORD=<trainer-password>
TRAINEE_USERNAME=<trainee-user>
TRAINEE_PASSWORD=<trainee-password>
COOKIE_SECURE=true
```

For enterprise deployment, replace this simple environment-backed login with the client's SSO/AD/LDAP integration rather than treating the bundled login as an enterprise identity system.

## Running locally

```powershell
python -m pip install -r requirements.txt

# Also install the Tesseract OCR binary and ensure `tesseract` is on PATH.
# On Windows, install Tesseract OCR separately (the Python binding is included in requirements.txt).

python -m uvicorn app.main:app --host 127.0.0.1 --port 8001
```

For the current local models:

```text
OLLAMA_HOST=http://127.0.0.1:11435
AI_TEXT_MODEL=llama3.2
AI_VISION_MODEL=qwen2.5vl:7b
AI_NUM_CTX=4096
```

For local voice demonstration:

```text
TTS_PROVIDER=kokoro
KOKORO_LANGUAGE=a
KOKORO_VOICE=af_heart
```

Azure Speech remains available as an explicit provider when client policy permits external TTS.

## Testing

The quality suite should be run from a clean directory/database:

```powershell
python -m compileall -q app tests
node --check app/static/portal.js
python -m unittest discover -s tests -v
python -m pip check
```

The test suite covers document structure, source numbering, scanned pages, action/explanation separation, compound actions, target ambiguity, highlight fallback, vision verification, drag paths, renderer/timeline contracts, frontend contracts, trainer review, publication gating, secure media boundaries, restart-safe persistence assumptions, and a real PDF -> plan -> audio -> MP4 orchestration path with model/TTS calls mocked.

## Production validation still required

This build is software-integration tested. A client release still needs a hardware-in-the-loop acceptance run using the actual configured `llama3.2`, `qwen2.5vl:7b`, OCR stack, TTS provider and representative confidential PDFs. The supplied local logs demonstrate real VRAM pressure/model reload behavior and a Qwen vision timeout; the routing design is intended to reduce those calls, but actual production latency and grounding accuracy must be measured on the target deployment hardware.


## Re-audit hardening

The release gate additionally verifies that unresolved targets do not abort video generation; they remain trainer-review blockers. Full-page UI fallbacks are classified as UI-capable evidence, OCR rejects the printed source instruction region before accepting a target, semantic repair can recover missing actions on partially recognized pages, required target review cannot be falsely completed without a point/path, prerequisite URLs are HTTP(S)-only, numeric source markers are normalized, and Tesseract is explicitly included as a Python dependency while the OS OCR binary remains a deployment prerequisite.
